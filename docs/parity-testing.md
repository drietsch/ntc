# Parity Testing

The CPU reference (`crates/ntc-model/src/cpu.rs` + `src/ops.rs`) is the
normative numerics. Every other execution path proves itself against it.

## Tiers

1. **Op-level** — each WGSL kernel vs the matching `ntc_model::ops` function
   on seeded random tensors (`crates/ntc-webgpu/tests`).
2. **Tiny-model level** — `fixtures/models/tiny-v1/tiny.ntc` (generated by
   `ntc fixture-gen`, seeded): full `WgpuBackend` vs `CpuRefBackend` head
   outputs. The Python exporter writes its own tiny model
   (`fixtures/models/tiny-v1-py/`) and the manifest is diffed via
   `ntc verify --dump-manifest` (format conformance).
3. **Decision level** — the runtime decodes both backends' outputs; predicted
   action / tool / presence / enum / span / datetime fields must agree 100%.
4. **Eval level (IC-2.5)** — PyTorch harness vs Rust runtime on real eval
   sets: ≥99.9% decision agreement; disagreements dumped for triage.

## Tolerances

Single source: `fixtures/tolerances.toml`. Element tolerances are
trend/debug metrics; **decision parity is the gate**.

## Debugging a divergence

- `ntc infer --model … --utterance … --tools …` runs the CPU path end-to-end.
- Layer-by-layer bisection: dump activations on both paths, find the first
  divergent tensor (naming matches `tensor_specs`), fix, re-run.
